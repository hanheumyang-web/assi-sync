# 사용자 흉내내기 (journey)

```bash
npm run test:journey          # 20동작
npm run test:journey 50       # 50동작
npm run test:journey 50 12345 # 씨앗 지정 — 같은 순서 재현
```

## 왜 이렇게 짰나

2026-09-07~08 에 사고가 여럿 났는데 공통점이 하나 있었다.

**생각해서 짜둔 시험은 전부 통과했다.** 터진 건 전부 생각 못 한 조합이었다 —
폴더를 지웠다 다시 만든 뒤 웹에서 삭제 신호가 온 경우,
카테고리가 바뀌어 파일이 옮겨진 경우, 영상 하나가 업로드 줄을 막은 경우.

그래서 경우를 다 적어두려 하지 않는다. 대신 **사용자가 실제로 하는 행동을
무작위로 섞어 돌리면서, 매 동작 뒤에 "절대 깨지면 안 되는 규칙" 을 전부 확인한다.**
어떤 조합에서 깨지든 여기서 걸린다.

## 구성

| 파일 | 무엇 |
|---|---|
| `actions.js` | 사용자가 하는 행동. "실제로 이렇게 쓰는 사람이 있나?" 를 통과한 것만 넣는다 |
| `invariants.js` | 절대 깨지면 안 되는 규칙. **이 파일이 심장이다** |
| `run.js` | 섞어서 돌리고, 매 동작마다 규칙을 확인한다 |

## 규칙을 추가할 때

"이게 깨지면 사용자가 무엇을 잃는가" 를 한 줄로 쓸 수 있어야 한다.
잃는 게 없으면 그건 규칙이 아니라 취향이다.

## 깨졌을 때

씨앗(seed)이 출력된다. 그 숫자로 다시 돌리면 **같은 순서가 그대로 재현된다.**
그때 그 상황을 다시 못 만들면 고칠 수가 없다.
현장(시험 폴더)도 지우지 않고 그대로 남긴다.

## 안전

- 테스트 계정으로만 돈다 (`~/Library/Application Support/assi-sync`)
- 만드는 것은 전부 `ZZ여정_` 로 시작한다. 그 밖의 것은 건드리지 않는다
- 시험 폴더는 `~/Desktop/_여정시험` — 실제 감시 폴더와 분리돼 있다
- 끝나면 웹의 `ZZ여정_` 프로젝트를 지우고 폴더도 치운다
